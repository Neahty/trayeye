# Бизнес - IT компания (АгроСкан) для iPhone

Нативное приложение под iOS: тот же сервер, та же база, тот же аккаунт - но со своей
иконкой на телефоне, без Telegram и без Safari.

`mobile/app` - **полная копия `client/`**, живущая своей жизнью. Telegram-версия
(`client/`) не зависит от этой папки и не меняется вместе с ней. Общий у них только
сервер (`server/`).

## Как это устроено

| | Telegram мини-апп (`client/`) | Приложение на iPhone (`mobile/app`) |
|---|---|---|
| Вход | `initData` от Telegram | одноразовый код из бота (`/pwa`) |
| Камера | `<input type="file" capture>` | системная камера iOS |
| Поделиться | окно Telegram | системное «Поделиться» iOS |
| Сборка | Vite → `dist` раздаёт Caddy | Vite → `dist` раздаёт Caddy по `/app/`, оболочка → `.ipa` |
| Обновления | сами, при каждом деплое | сами, при каждом деплое |

## Обновления

Внутри `.ipa` лежит **только нативная оболочка** - интерфейс она грузит с
`https://shekspireteam.ru/app/` (`server.url` в `capacitor.config.json`). Поэтому
обычный деплой обновляет и приложение на телефоне: перезапустил - увидел новую версию.
Пересобирать `.ipa` не нужно.

Раздача устроена без правки Caddy: `deploy.sh` кладёт сборку в `client/dist/app`,
а эту папку Caddy уже отдаёт как статику. Маршруты внутри приложения живут в хеше
(`/app/#/history`) - так сервер всегда видит только один адрес, и перезагрузка на
любом экране возвращает приложение, а не Telegram-версию из корня домена.

`server.url` указывает на `/app/index.html`, а не на `/app/`: правило
`try_files {path} /index.html` в корневом блоке Caddy не подставляет `index.html`
для вложенной папки, и голый `/app/` отдал бы Telegram-версию.

Пересборка нужна только когда меняется сама оболочка: версия Capacitor, список
плагинов, иконка, заставка, разрешения в `Info.plist`.

Без интернета приложение показывает заглушку `public/error.html` - работать офлайн
оно всё равно не может, все данные лежат на сервере.

Вход снаружи Telegram: бот по команде `/pwa` (только админам) выдаёт шестизначный код,
приложение меняет его на обычный 30-дневный токен через `POST /api/auth/pwa`.
Код одноразовый, живёт 15 минут, хранится в памяти сервера
(`server/src/services/appLoginCodes.js`).

## Сборка `.ipa`

Собирать надо на macOS, поэтому сборка живёт в GitHub Actions:

1. Actions → **«Сборка приложения для iPhone»** → Run workflow.
2. Через ~6 минут скачать артефакт `Bytwise-ipa`.

Xcode-проект (`mobile/app/ios/`) в репозитории не хранится - он целиком выводится из
`capacitor.config.json`, `package.json` и `assets/`, и генерируется в CI заново.

Приватный репозиторий даёт 2000 минут в месяц, но macOS считается ×10 - то есть
**200 macOS-минут**, примерно 30 сборок.

## Установка на телефон (Windows, бесплатно)

1. Поставить [Sideloadly](https://sideloadly.io) и Apple Devices (iTunes).
2. Подключить iPhone кабелем, перетащить `Bytwise.ipa` в Sideloadly, ввести свой
   обычный Apple ID.
3. На телефоне: Настройки → Основные → VPN и управление устройством → доверять профилю.
4. Открыть Bytwise, отправить боту `/pwa`, ввести код. Один раз.

Подпись бесплатного Apple ID живёт 7 дней - её продлевает демон Sideloadly по WiFi,
пересобирать `.ipa` для этого не нужно. Больше трёх таких приложений на бесплатном
аккаунте одновременно держать нельзя.

## Локальная разработка с Windows

```bash
cd mobile/app
npm install
npm run dev
```

Экраны открываются в браузере: нативные вызовы (камера, вибрация, «Поделиться»)
подменяются веб-аналогами, см. `src/lib/native.js`. Проверить можно всё, кроме
собственно нативной обёртки.

## Чего нет

- **Пуш-уведомлений от iOS** - нужен APNs и платный аккаунт Apple ($99/год).
  Напоминания по-прежнему приходят в Telegram от бота.
- **App Store** - тоже только с платным аккаунтом.
