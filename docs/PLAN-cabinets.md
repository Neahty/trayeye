# TrayEye: разбор базы и план кабинетов «Директор» и «Комбинат»

Статус: логика реализована (сервер + `web/` без дизайна), см. п. 9. Дата: 13.10.2026. Сдача: 21.10.2026.

## 1. Что есть сейчас (база Bytwise)

| Слой | Что | Пригодится? |
| --- | --- | --- |
| `server/` | Node + Express + PostgreSQL (`pg`, сырой SQL), JWT, multer, node-cron, telegraf | **Да**: каркас API, БД, загрузка фото, ИИ-цепочка |
| `server/src/services/openai.js` | Цепочка Gemini (бесплатно) → OpenAI (платно), фото → `dishes[]` (название, ккал, вес, confidence) | **Да**: меняем промпт на «поднос → блюда + % остатка» |
| `server/src/routes/scan.js` | Приём фото, сохранение в `uploads/`, запись в `scans` | **Да**, как образец эндпоинта сканирования подноса |
| `admin/` | React 18 + Vite, десктопная раскладка с боковым меню (`Layout.jsx`), recharts | **Да**: ближе всего к макету по раскладке; тему перекрашиваем в зелёно-синюю |
| `client/`, `mobile/app/` | Telegram-мини-приложение и копия для iPhone (подсчёт калорий) | Нет, для кабинетов не нужно |
| Подписки, ЮKassa, тренеры, квесты, рефералы, рассылки, бот поддержки | Логика Bytwise | Нет, не трогаем, в новые кабинеты не тянем |
| `web/`, `android/` | Пустые папки | `web/` → сюда новая платформа |

Вход сейчас только через Telegram `initData` (`routes/auth.js`) или пароль админа. Для кабинетов нужен новый вход: по именной ссылке.

Схема БД (`server/src/db/schema.sql`) заточена под людей, которые считают калории (`users`, `scans`, `subscriptions`…). Школ, классов, блюд-каталога и меню нет, это добавляем новыми таблицами.

Деплой отключён (`deploy.yml` → `if: false`), имена `/opt/bytwise` и systemd-сервисов менять нельзя, это сломает живой Bytwise.

## 2. Что в макетах (по фото, файл Figma недоступен, см. п. 8)

Общий каркас (десктоп): слева блок аватарки (серый прямоугольник, картинку пришлют) и меню, внизу «Выйти»; сверху по центру название организации, справа круглые иконки и переключатель темы.

**Директор** (`директор\…`), шапка «Гимназия №33», меню: Главная · Классы · Статистика · Меню · Настройки
- **Главная**: «Добрый день, Анна Петровна!», «Сегодня 12 октября, среда»;
  3 карточки: *Списания 7% (было 20%)*, *Экономия 12 400 ₽ за сегодня*, *Детей 847/900, 94% пришли*;
  «Прогноз на завтра»: блюдо, «420 порций (обычно 480)», «60» со стрелкой (разница);
  «Рекомендации»: «В среду дети едят меньше. Уменьшите порции на 10%»;
  кнопки «Открыть статистику» и «Посмотреть меню».
- **Меню** (фрейм назван «статистика», заголовок «Меню»): сетка 3×3 карточек блюд (картинка, «Борщ», «10 шт», «100%»), кнопка «+ Добавить меню».
- **Классы**: виден только краешек фрейма, нужен экспорт.

**Комбинат** (`комбинат\…`), шапка «ПОЛИГРАФ КОМБИНАТ», меню: Главная · Школы · Статистика · Поставщики · Настройки
- **Меню товаров** (фрейм «статистика»): сетка 3×3 карточек (картинка, «Борщ», «10 шт \ 2 кг», «Школы: 11, 21», «ООО "МясоПтица"»).
- Слева виден ещё один экран комбината (кнопки, обведённая кнопка «…бинат»), нужен экспорт.

Картинки блюд: временно берём из интернета или генерируем; в боевой версии они приходят из базы товаров производства.

## 3. Решения из переписки

- Делаем **веб-платформу для десктопа**, не Telegram-бота и не Android. Механику берём от бота Bytwise.
- **Регистрации нет.** Комбинат создаёт **личную ссылку** (ФИО директора + номер школы) → отправляет директору → директор входит по ней. Данные школы подгружаются автоматически.
- Хакатон не IT-шный, поэтому нужен **рабочий пример** (демо на сидовых данных), а не боевая система.

## 4. Модель данных (новые таблицы, рядом с существующими)

```
kombinats      id, name                                   -- «Полиграф комбинат»
suppliers      id, kombinat_id, name                      -- «ООО МясоПтица»
schools        id, kombinat_id, number, name              -- 33, «Гимназия №33»
directors      id, school_id, full_name, avatar_url
access_links   id, role(director|kombinat), subject_id, token_hash, created_at, revoked_at
classes        id, school_id, name, students_count        -- «5А», 28
dishes         id, kombinat_id, supplier_id, name, image_url, portion_grams, portion_price
menu_days      id, school_id, date
menu_items     id, menu_day_id, dish_id, planned_portions
attendance     id, school_id, class_id, date, present_count
tray_scans     id, school_id, dish_id, photo_path, leftover_pct, ai_confidence, created_at
```

Формулы для карточек (считаем на сервере):
- **Списания %** = Σ(остаток × порция) / Σ(выдано × порция) за день; «было» = то же за первую неделю (до системы).
- **Экономия ₽** = Σ(обычно − по прогнозу) × цена порции.
- **Детей** = Σ `attendance.present_count` / Σ `classes.students_count`.
- **Прогноз на завтра** = среднее съеденное по этому дню недели за 4 недели × ожидаемая явка; «обычно» = `planned_portions`.
- **Рекомендации**: правила поверх статистики (день недели с низким потреблением, блюдо с остатком > 50% → «заменить»). ИИ-текст можно добавить позже.

## 5. API (новые роуты, старые не трогаем)

```
POST /api/cabinet/login            { token } → cookie/JWT с ролью и subject_id
GET  /api/cabinet/me               кто вошёл, школа/комбинат, аватар

# директор
GET  /api/school/dashboard         карточки + прогноз + рекомендации
GET  /api/school/menu?date=        карточки меню (блюдо, шт, % съедаемости)
POST /api/school/menu              «Добавить меню»
GET  /api/school/classes           классы и явка
GET  /api/school/stats?from=&to=   графики по блюдам

# комбинат
GET  /api/kombinat/products        «Меню товаров» (блюдо, шт\кг, школы, поставщик)
GET  /api/kombinat/schools         список школ + показатели
POST /api/kombinat/links           создать именную ссылку директору (ФИО + № школы)
GET  /api/kombinat/stats
GET  /api/kombinat/suppliers

# камера / демо
POST /api/tray/scan                фото подноса → ИИ → tray_scans
```

Проверка доступа: middleware `cabinetAuth(role)` по аналогии с `middleware/auth.js`; директор видит только свою школу, комбинат только свои школы.

## 6. Фронтенд

Новое приложение в `web/` (React 18 + Vite, axios, react-router, recharts — стек как в `admin/`).
Каркас `Layout` (боковое меню + шапка) один на обе роли, пункты меню зависят от роли. Маршруты:
`/d/:token` (вход директора по ссылке), `/director/{home,classes,stats,menu,settings}`,
`/kombinat/{home,schools,stats,suppliers,settings}`.
Цвета и шрифт снимаем с макета: зелёный акцент, синие заголовки, светлый фон, карточки со скруглением. Тёмная тема через переключатель в шапке.

## 7. Этапы (8 дней до 21.10)

1. **Доступ к макетам**: экспорт всех фреймов, токены цветов и шрифтов, аватарка.
2. **Сервер**: миграция новых таблиц + сид демо-данных (комбинат, 2–3 школы, классы, 2 недели сканов) + вход по ссылке.
3. **Кабинет директора**: Главная → Меню → Статистика → Классы.
4. **Кабинет комбината**: Меню товаров → Школы (+ создание ссылки) → Статистика → Поставщики.
5. **Сканирование подноса**: промпт «что осталось» в `openai.js`, демо-загрузка фото.
6. **Деплой демо**: отдельный поддомен/путь и отдельный сервис, не трогая прод Bytwise.
7. **Тесты** (jest на сервере: формулы, доступ по ссылке) и прогон экранов в браузере против макета.
